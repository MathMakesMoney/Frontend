# upload (작업 만들기)

시험지 파일 하나로 작업을 만든다. (F1) 기준: `../Backend/.../job/CLAUDE.md` 입력, `job/presentation/CLAUDE.md`

## 요청

`POST /api/jobs` (multipart) -> `{"id", "status"}` -> 작업 상세로 이동

| 필드 | 필수 | 설명 |
|---|---|---|
| `file` | O | PDF, HWP, HWPX, HML 하나. 최대 50MB (제안) |
| `features` | X | 만들 기능 쉼표 글자 (`typing,haesol,variant`). 화면은 늘 보낸다 (아래 기능 고르기) |
| `title` | O | 해설지 제목 |
| `scope` | O | 교과 범위 문구 (예 문구는 `solution/infrastructure/ai/CLAUDE.md`) |
| `pages` | PDF 만 | 쪽 범위, 예 `1-8,13-16` |
| `school`, `grade`, `exam`, `range` | X | 해설지 머리말용 학교, 학년, 시험 이름(예 2023학년도 2학기 중간고사), 시험 범위(예 수학(하) 집합~함수). 비우면 임시 문구로 들어가고 한글에서 고칠 수 있다고 안내 |
| `mode` | O | `api` 또는 `mcp` |

## 화면 규칙

- HML (학원 시험지 타이핑 1단계, 계획 `../Backend/docs/exec-plans/active/academy-typing-server.md`): AI 단계 없이 업로드 때 학원 양식 문서가 바로 만들어진다. 그래서 파일이 `.hml` 이면 AI 이용 방식(MCP/API)과 시험 범위 칸을 숨긴다(머리 표 과목 칸은 교과 범위). 시험 정보 칸 안내는 학원 양식 머리 표에 들어간다는 뜻(시험 이름=연도·시험 칸, 학교를 비우면 시험지의 학교). 검사 실패는 백엔드 400 사유를 기존 오류 줄에 그대로 보인다

- 입력 권장 순서를 안내한다: HWPX > HWP > PDF (HWPX·HWP 가 추출이 더 정확하고 싸다)
- 확장자·크기는 먼저 화면에서 막고, 내용 검사(암호, 배포용 HWP, 쪽 수 초과, 형식 불명)는 백엔드 400 사유를 그대로 보여 준다
- PDF 일 때만 쪽 범위 칸을 보인다. 수능처럼 선택과목이 여럿 든 PDF 는 쪽 범위를 안 넣으면 23~30번이 세 번 나와 31~54번으로 밀린다고 안내한다
- 공통·선택 PDF 가 따로면 1차는 한 파일로 합쳐 올리라고 안내 (다중 파일은 2차)
- 업로드 중 진행률 표시, 두 번 누름 막기

### 쪽 범위 검사 테스트 (순수 함수, 먼저 테스트)

- 통과: `1-8,13-16`, `3`, `1-8, 13-16` (공백 허용)
- 거부: `8-1`, `0-3`, `a-b`, `1--3`, 빈 조각 `1,,3`
- 최종 판단(총 쪽 수 초과 등)은 백엔드

## 학원 시험지 묶음·기능 고르기 (사이트 2단계, 계획 `../Backend/docs/exec-plans/active/academy-batch.md`)

- 파일 선택은 여러 개, 폴더째 선택도 된다 (`batchFiles.ts` `pickFiles`). 지원하는 파일(hml·hwp·hwpx·pdf)이 2개 이상이면 묶음(형식을 섞어도 되고 이름순, 지원하지 않는 파일은 못 넣었다고 알림), 하나면 그 파일. 폴더의 `.DS_Store` 같은 점 파일은 알리지 않는다 (4단계, 계획 `../Backend/docs/exec-plans/active/academy-typing-ai.md`)
- 같은 시험지 다른 형식 (`sameExam.ts`): 같은 폴더에서 확장자(hml·hwp·hwpx·pdf, 대소문자 무시)를 뗀 이름이 같으면 한 묶음으로 보고, 올리기 화면에서 알린 뒤 라디오로 하나만 고르게 한다. 고르기 전에는 올리기 버튼을 막고, 고른 것만 보낸다. 폴더째 고를 때 다른 폴더의 같은 이름은 다른 시험지다 (1반/중간.hml 과 2반/중간.hml 을 하나로 합치면 진짜 시험지가 사라진다. 놓치는 쪽은 지금과 같은 상태라 비용만 든다). 서버는 막지 않는다
- 묶음: `POST /api/batches` (`createBatch`). 묶음 이름, 공통 값(교과 범위·학교·학년·시험 이름·기능)과 `모든 시험지에 적용`(빈 칸은 시험지 값을 지우지 않고 기능은 덮어쓴다), 시험지마다 제목(파일명에서)·같은 칸들. 시험지마다만 있는 칸(`FileFields`): PDF 는 쪽 범위(`pages`, 단일 업로드와 같은 형식 검사), hml 이 아니면 시험 범위(`range`). hml 의 시험 범위는 빈 값
- 응답 `errors` 가 있으면 파일별 사유를 보이고 `묶음 화면으로` 링크를 준다 (없으면 바로 `/batches/{id}`). 하나도 못 만들면 400 사유를 기존 오류 줄에 보인다
- 기능 체크 타이핑·해설·변형 (`FeaturePicker`, 모든 형식): 변형을 켜면 해설이 같이 켜지고 변형이 켜진 동안 해설은 끌 수 없다 (`toggleFeature`). 하나도 안 고르면 막는다. 단일 업로드는 `POST /api/jobs` 에 `features`(쉼표 글자)를 늘 보낸다. 파일을 고르면 기본은 hml 타이핑, hwp·hwpx·pdf 해설 (지금까지 받던 해설지를 그대로 받게, 백엔드 계획의 확인 필요). 묶음 줄 기본은 타이핑
- AI 이용 방식(MCP/API)은 AI 를 쓸 때만 보인다: hwp·hwpx·pdf 는 문항 뽑기부터 AI, hml 은 해설을 고를 때만 (타이핑만인 hml 은 숨김). 값은 기존 `mode` 쿼리를 따르고 서버에는 보내지 않는다
