# upload (작업 만들기)

시험지 파일 하나로 작업을 만든다. (F1) 기준: `../Backend/.../job/CLAUDE.md` 입력, `job/presentation/CLAUDE.md`

## 요청

`POST /api/jobs` (multipart) -> `{"id", "status"}` -> 작업 상세로 이동

| 필드 | 필수 | 설명 |
|---|---|---|
| `file` | O | PDF, HWP, HWPX 하나. 최대 50MB (제안) |
| `title` | O | 해설지 제목 |
| `scope` | O | 교과 범위 문구 (예 문구는 `solution/infrastructure/ai/CLAUDE.md`) |
| `pages` | PDF 만 | 쪽 범위, 예 `1-8,13-16` |
| `school`, `grade`, `exam`, `range` | X | 해설지 머리말용 학교, 학년, 시험 이름(예 2023학년도 2학기 중간고사), 시험 범위(예 수학(하) 집합~함수). 비우면 임시 문구로 들어가고 한글에서 고칠 수 있다고 안내 |
| `mode` | O | `api` 또는 `mcp` |

## 화면 규칙

- 입력 권장 순서를 안내한다: HWPX > HWP > PDF (HWPX·HWP 가 추출이 더 정확하고 싸다)
- 확장자·크기는 먼저 화면에서 막고, 내용 검사(암호, 배포용 HWP, 쪽 수 초과, 형식 불명)는 백엔드 400 사유를 그대로 보여 준다
- PDF 일 때만 쪽 범위 칸을 보인다. 수능처럼 선택과목이 여럿 든 PDF 는 쪽 범위를 안 넣으면 23~30번이 세 번 나와 31~54번으로 밀린다고 안내한다
- 공통·선택 PDF 가 따로면 1차는 한 파일로 합쳐 올리라고 안내 (다중 파일은 2차)
- 업로드 중 진행률 표시, 두 번 누름 막기

### 쪽 범위 검사 테스트 (순수 함수, 먼저 테스트)

- 통과: `1-8,13-16`, `3`, `1-8, 13-16` (공백 허용)
- 거부: `8-1`, `0-3`, `a-b`, `1--3`, 빈 조각 `1,,3`
- 최종 판단(총 쪽 수 초과 등)은 백엔드
